# 短信模板送审样例（对接运营商/短信通道时使用）
#
# 铁律（Apple《Enabling AutoFill for domain-bound SMS codes》）：
# 1. 最后一行必须是 `@裸DNS域名 #验证码`，两者用一个空格分隔；
# 2. 域名不能带 https://、不能带路径；
# 3. 通道签名、营销尾巴只能放在正文区域，严禁追加在绑定行之后；
# 4. iframe 嵌入式登录才需要 `%附加域名`，普通场景不要加。

## 模板 A：标准域名绑定模板（推荐，一次送审长期使用）
【示例银行】您正在登录手机银行，验证码${code}，5分钟内有效，请勿泄露给他人。
@bank.example #${code}

## 模板 B：独立登录子域（App 关联域与短信域名必须一致）
【示例银行】您正在进行网银登录，验证码${code}，请勿泄露。
@auth.bank.example #${code}

## 模板 C：iframe 嵌入式登录（第三方容器内的登录组件）
【示例银行】验证码${code}，请勿泄露。
@bank.example #${code} %iframe-auth.example.org

## 反面示例（禁止送审/上线）

# ✗ 通道签名跟在绑定行后面：绑定行不再是最后一行，系统识别失败
【示例银行】验证码123456
@bank.example #123456
【示例银行】

# ✗ 域名带协议头/路径：Apple 只接受裸 DNS 域名
@https://bank.example/login #123456

# ✗ 全角符号且未做归一化（App 侧已兼容全角，但部分安卓/旧机不识别，送审用半角）
＠bank.example　＃123456

# ✗ 绑定行与正文挤在同一行：必须独立成行
您的验证码123456 @bank.example #123456
